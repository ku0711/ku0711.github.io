SDK 壓測系統

為 SDK 後端服務自建的一整套壓測工具鏈：桌面工具設計壓測情境， Grafana 自製 App Plugin 直接當控制台，壓測本體以 Pod 形式在 k8s 上依需求啟動、多場並行。

自建工具鏈
最高 3000 bots 併發 多場次並行 C# / .NET Kubernetes Grafana App Plugin WinForms

情境設計

  • 固定流程：依序執行指定端點，模擬完整業務流
  • 隨機權重：20+ 支端點依機率分佈隨機呼叫
  • 有狀態模式：沿流程累積 token 與訂單編號，貼近真實串接行為
  • 步驟間隔隨機化、請求逾時與失敗重試策略可調

執行與控制

  • 待命 Pod：常駐 runner 提供控制 API，管理佇列、TTL 與 SIGTERM 轉發
  • 參數覆寫：同一份情境可調整 bot 數與迴圈次數重複掛載
  • 情境／行為檔／測試資料以 ConfigMap 掛載，不需重建映像
  • 執行歷史與即時狀態直接呈現在 Grafana 面板

SDK Server 端 API

以 C# / .NET 新寫的三組後端流程，涵蓋跨情境登入憑證、推播派送與第三方金流派獎。

C# / .NET

OTT 單次票證交換

把既有登入態轉換成一組短效的臨時憑證，供 WebView 等外部情境使用。

一次性票證 Token Rotation 短效期
票證用過即廢；refresh token 旋轉後舊憑證立即失效，僅最新一組有效。

Firebase 推播

發送與送達分離的非同步推播介面，並自動回收失效的裝置 Token。

HMAC 簽章 背景佇列 失效 Token 回收
限流以 Token 數計算，因此設計失效回收機制，把有限額度留給真正送得到的裝置。

第三方金流支付與派獎

建立外部支付訂單、驗證回調簽章，再依遊戲別派發獎勵，並含失敗補償機制。

Strategy Pattern 回調驗簽 ACK / 重試補償
派獎 Handler 採策略模式，新遊戲只要實作介面並註冊即可接上，不動既有流程。

SDK 客戶端第三方插件串接

在 Unity 客戶端整合數據、推播與當機回報等第三方服務，並排除舊版引擎與原生層之間的相容問題。

Unity · Android · iOS
AppsFlyer Firebase Analytics Firebase Messaging Crashlytics Facebook SDK WebView

舊版引擎相容性排查

  • Android 高 API 等級閃退：舊版 Unity 在 Development Build 打包至較新 API 等級時， 因廣播接收器註冊未帶必要旗標，觸發系統嚴格檢查而閃退 — 排查筆記
  • iOS 跳轉商店失效：舊版 Unity 的開啟外部連結 API 在新版 iOS 無法運作， 底層呼叫到已棄用的原生方法 — 排查筆記
  • 過審升級連鎖問題：第三方插件因商店審查要求升級，需一併調整 JDK 與 Gradle 版本
